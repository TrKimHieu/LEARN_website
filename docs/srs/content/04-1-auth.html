4. Yêu cầu chức năng chi tiết (Specific Functional Requirements)

Chương này chia theo module (epic). Mỗi module có bảng FR kèm trạng thái và route thật (đối chiếu apps/api/src/modules/**/*.controller.ts), sau đó đặc tả sâu các chức năng trọng yếu theo khung: Mô tả logic · Luồng xử lý (Sequence) · Xử lý ngoại lệ. FR là CRUD thẳng, không có logic đáng kể, chỉ nằm trong bảng FR.

Quy ước chung cho mọi endpoint. Tiền tố /api/v1. Endpoint cần đăng nhập nhận header Authorization: Bearer <accessToken>; thiếu/sai → 401 UNAUTHENTICATED. Body/param/query sai Zod schema → 400 VALIDATION_FAILED (kèm meta.fields). Tài nguyên không tồn tại hoặc không thuộc về người gọi → 404 NOT_FOUND (không phân biệt, để không lộ sự tồn tại của dữ liệu người khác). Lỗi không lường trước → 500 INTERNAL_ERROR với message chung. Bảng lỗi ở từng chức năng chỉ liệt kê các trường hợp đặc thù ngoài quy ước này.

4.1 Module Authentication (FR-AUTH) [SPEC §6.1]

Đăng ký, đăng nhập, duy trì phiên, đăng xuất, hồ sơ và đặt lại mật khẩu. Access token ngắn hạn giữ trong memory của web app; refresh token dài hạn nằm trong cookie httpOnly và được xoay vòng mỗi lần dùng.

4.1.1 Chức năng: Đăng ký & Đăng nhập (JWT + refresh token)

FR-AUTH-01, FR-AUTH-02 · NFR-SEC-01/02/03

Mô tả logic
  • Đăng ký: validate registerSchema (email ≤ 254 ký tự, chuyển chữ thường; mật khẩu 8–72 ký tự; displayName 2–100; locale vi|en). Hash mật khẩu bằng argon2id (memoryCost 19456, timeCost 2, parallelism 1) rồi INSERT User. Không "kiểm tra email rồi mới ghi": ràng buộc UNIQUE(email) là thứ quyết định, lỗi P2002 được bắt và trả 409 — hai request đăng ký cùng email đồng thời không gây 500. Tạo Subscription gói FREE, cấp token như đăng nhập, trả 201. Rate limit 10 lần/60 giây/IP.
  • Đăng nhập: rate limit 5 lần/60 giây theo IP + route (bộ đếm Redis INCR có TTL). Tìm user theo email và luôn chạy argon2 verify — khi không có user thì verify trên một hash giả — để thời gian phản hồi không tiết lộ email nào đã đăng ký. Sai email hoặc mật khẩu trả cùng một thông điệp.
  • Cấp token: access token là JWT HS256 (sub, role, email), hạn JWT_ACCESS_TTL = 15 phút, thuật toán được ghim khi xác minh. Refresh token là chuỗi ngẫu nhiên 256-bit; DB chỉ lưu SHA-256 kèm familyId mới, userAgent, ipAddress, expiresAt = +30 ngày. Cookie refresh_token: httpOnly, SameSite=Lax, Secure ở production, path=/.
  • Phía web: access token chỉ giữ trong memory (không localStorage). Khi tải lại trang hoặc access token hết hạn, web gọi /auth/refresh để lấy token mới.

4.1.2 Chức năng: Làm mới phiên (Refresh token rotation & reuse detection)

FR-AUTH-03, FR-AUTH-04 · NFR-SEC-03

Mô tả logic
  • Đọc cookie refresh_token, tính SHA-256, tìm bản ghi. Mỗi lần refresh hợp lệ: trong một transaction revoke token cũ và tạo token mới cùng familyId; ký access token mới; set cookie mới.
  • Reuse detection: nếu token tìm thấy đã có revokedAt (tức ai đó dùng lại một token đã được xoay), coi như token bị đánh cắp → revoke toàn bộ family, buộc đăng nhập lại.
  • Token hết hạn bị revoke và trả 401. User đã bị xoá → 401.
  • Logout revoke token hiện tại và xoá cookie. Logout-all revoke mọi refresh token của user. Access token đã cấp vẫn sống tối đa 15 phút (không có blacklist) — chấp nhận được vì hạn ngắn.

4.1.3 Chức năng: Quên & đặt lại mật khẩu

FR-AUTH-07 · BR-13

Mô tả logic
  • Bước 1 — POST /auth/forgot-password: luôn trả 200 { ok: true } với cùng một câu dù email có tồn tại hay không. Request chỉ chờ bước tra cứu user (giống nhau ở hai nhánh); phần phát token, ghi DB và gửi thư chạy nền, để thời gian phản hồi không lộ email đã đăng ký. Giới hạn 5 request/15 phút/IP (guard) và tối đa 3 thư/giờ/email (bộ đếm Redis theo hash email).
  • Phát token: chuỗi 256-bit, DB lưu SHA-256, hạn PASSWORD_RESET_TTL_MIN (30 phút). Trong một transaction: vô hiệu mọi token cũ của user rồi tạo token mới — mỗi lúc chỉ một đường dẫn còn hiệu lực. Gửi thư chứa {APP_URL}/reset-password?token=…. MAIL_MODE=log (dev) in đường dẫn ra log; MAIL_MODE=smtp gửi thật qua SMTP_URL. Ghi AuditLog auth.password_reset_requested.
  • Bước 2 — POST /auth/reset-password: token sai, hết hạn hay đã dùng đều trả cùng một lỗi. Nếu hợp lệ, trong một transaction: đánh dấu usedAt bằng update có điều kiện (hai request cùng token chỉ một cái thắng), cập nhật passwordHash, vô hiệu token reset khác, revoke mọi refresh token (đăng xuất mọi thiết bị). Xoá cookie phiên hiện tại. Ghi AuditLog auth.password_reset. Giới hạn 10 request/15 phút/IP.

4.1.4 Chức năng: Hồ sơ & đổi mật khẩu

FR-AUTH-05, FR-AUTH-06

Mô tả logic
  • GET /auth/me trả user (không có passwordHash), gói hiện tại plan { code, name } và usage. PATCH /auth/me chỉ nhận displayName, locale (schema strict — field lạ bị từ chối).
  • POST /auth/change-password xác minh currentPassword bằng argon2 rồi hash mật khẩu mới.
