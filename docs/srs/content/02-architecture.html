2. Mô tả kiến trúc tổng thể (Overall Description)

2.1 Kiến trúc hệ thống (System Architecture)

LEARN là một modular monolith đặt trong monorepo TypeScript (npm workspaces), tách thành ba tiến trình chạy độc lập và các package dùng chung:

  • apps/web — Next.js 15 (App Router). Gồm trang portfolio công khai và ứng dụng học tập cần đăng nhập. Gọi API qua REST, giữ access token trong memory, refresh token nằm trong cookie httpOnly.
  • apps/api — NestJS 11, REST dưới /api/v1. Chia module theo domain: auth, courses, documents, ai, learning, subscriptions, admin, health. Mỗi module theo lớp Controller → Service → Repository; repository là nơi duy nhất truy vấn Prisma và bắt buộc lọc quyền sở hữu (ADR 005).
  • apps/worker — NestJS standalone (không mở HTTP), tiêu thụ hai hàng đợi BullMQ: document-extract (concurrency 4) và lesson-generate (concurrency 2). Tách khỏi API để việc gọi LLM chậm không chiếm tài nguyên request và để scale độc lập.
  • packages/contracts (Zod schema + kiểu dùng chung web/api/worker), packages/db (Prisma client, argon2, uuidv7), packages/ai (adapter LLM, prompt có version, chunker, validator 4 tầng), packages/ui, packages/config.

Các thành phần tương tác như sau: trình duyệt gọi web; web gọi API bằng Bearer JWT. API đọc/ghi PostgreSQL, ký presigned URL để trình duyệt PUT file thẳng lên object storage, và đẩy job vào Redis. Worker nhận job, đọc file từ storage, gọi LLM, ghi kết quả vào PostgreSQL và publish tiến độ qua Redis pub/sub. Bên thứ ba: LLM provider, SMTP, Stripe (Đã lên kế hoạch).

Môi trường chạy & triển khai

Khi phát triển, hạ tầng chạy bằng Docker Compose (PostgreSQL, Redis, MinIO + job tạo bucket); ba tiến trình ứng dụng chạy bằng npm run dev. CI trên GitHub Actions chạy lint, typecheck, unit test, build, audit và integration test với PostgreSQL/Redis thật. Mỗi tiến trình có Dockerfile riêng trong infra/. Thứ tự deploy an toàn: migration → worker → api → web.
