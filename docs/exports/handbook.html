01

Dự án này là gì

Một nền tảng biến tài liệu học tập thành khóa học và bài học tương tác bằng AI — và một website portfolio trình bày nó. Hai thứ tách biệt, đừng nhầm.

Định vị sản phẩm

Turn your documents into interactive learning

Người dùng tải PDF, slide bài giảng và tài liệu cá nhân vào một Course. AI phân tích rồi sinh ra Lesson, Exercise, câu hỏi và feedback. Người học luyện tập qua trải nghiệm tương tác lấy cảm hứng từ các ứng dụng học ngôn ngữ. SPEC

02

Bối cảnh nghiệp vụ

Vấn đề phải nói cụ thể, không thay bằng ngôn ngữ marketing mơ hồ. Đây là ràng buộc của spec, không phải sở thích.

Vấn đề — bốn biểu hiện cụ thể

  • Tài liệu học bị phân mảnh, nằm rải rác nhiều nguồn.
  • Tài liệu tĩnh khó học chủ động — đọc xong không biết mình nhớ được gì.
  • Tự soạn bài học và bài tập tốn rất nhiều thời gian.
  • Khó duy trì tiến độ vì thiếu cấu trúc và phản hồi.

Mục tiêu: chuyển người học từ tiêu thụ thụ động sang học chủ động.

Sáu giá trị sản phẩm

  • Giảm thời gian chuẩn bị học
  • Học chủ động — tài liệu thành câu hỏi và hoạt động
  • Học có cấu trúc — Course → Lesson → Exercise
  • Theo dõi tiến trình học
  • AI hỗ trợ chuyển đổi nội dung và sinh bài tập
  • Mô hình SaaS nhiều gói, nhiều hạn mức

Không tuyên bố học cá nhân hóa hoàn toàn hay adaptive trừ khi thực sự đã làm.

03

Phạm vi

Luồng lõi phải chạy thông suốt đầu-cuối. Mọi thứ ngoài danh sách bên phải là roadmap, và phải được gắn nhãn đúng trên website.

Luồng lõi MVP

Đăng ký → Tạo Course → Upload Document → AI sinh Lesson
→ Học Lesson → Làm Exercise → Theo dõi tiến trình

Trong phạm vi — 8 nhóm chức năng

  • Authentication — đăng ký, đăng nhập, hồ sơ, bảo vệ route
  • Course — tạo, liệt kê, chi tiết, đổi tên, xoá, gắn tài liệu
  • Document — upload, metadata, trạng thái xử lý, xử lý lỗi
  • AI sinh bài học — tạo job, sinh Lesson + Exercise, validate trước khi lưu
  • Học tương tác — trả lời, nộp bài, điểm, feedback, đánh dấu hoàn thành
  • Tiến trình — bài đã xong, kết quả, tiến độ Course, lịch sử
  • Subscription — gói, giá, tính năng, áp hạn mức
  • Admin — xem user, course, AI job, subscription

Lối thoát

Worker gọi DocumentParser qua interface, không gọi thư viện trực tiếp. Nếu chất lượng trích xuất thành nút thắt — đo bằng tiêu chí ở mục 08 — tách một service Python chỉ làm parse. Ghi ADR khi đổi.

model Document {
  id             String         @id @default(uuid(7))
  courseId       String
  filename       String
  mimeType       String
  sizeBytes      Int
  storageKey     String         @unique
  checksumSha256 String
  pageCount      Int?
  status         DocumentStatus @default(PENDING)
  errorCode      String?        // mã lỗi ổn định
  errorMessage   String?        // thông điệp cho người dùng

  @@index([courseId, status])
  @@index([courseId, checksumSha256])  // phát hiện trùng
}
enum DocumentStatus { PENDING UPLOADED EXTRACTING EXTRACTED FAILED }
model AIJob {
  id             String      @id @default(uuid(7))
  courseId       String
  documentId     String?     // null = sinh từ cả Course
  type           AIJobType
  status         AIJobStatus @default(QUEUED)
  progress       Int         @default(0)
  progressLabel  String?     // "Đang sinh bài 3/7"
  attempt        Int         @default(0)
  idempotencyKey String      @unique
  inputParams    Json
  error          Json?

  @@index([status, queuedAt])
}
enum AIJobStatus { QUEUED RUNNING SUCCEEDED FAILED CANCELLED }
model GenerationRun {
  aiJobId          String
  step             String   // outline | lesson | exercise
  model            String
  promptVersion    String   // "outline@3"
  inputTokens      Int
  outputTokens     Int
  costUsd          Decimal  @db.Decimal(10, 6)
  latencyMs        Int
  rawResponseKey   String?  // storage, giữ 30 ngày
  validationReport Json?
}
model Lesson {
  courseId         String
  aiJobId          String?  // null = người dùng tự tạo
  orderIndex       Int
  title            String
  contentMd        String   @db.Text
  status           LessonStatus @default(DRAFT)
  sourceChunkIds   String[]  // truy vết về tài liệu gốc
  editedByUserAt   DateTime? // người dùng đã sửa

  @@unique([courseId, orderIndex])
}
model UsageCounter {
  userId String
  period String  // "2026-09"
  metric UsageMetric
  value  Int    @default(0)

  @@unique([userId, period, metric])

}
model PaymentEvent {
  provider     String   // "stripe"
  eventId      String   // id bên nhà cung cấp

  payload      Json

}
Migration và seed
  • Mỗi thay đổi schema là một migration có tên mô tả: 20260920_add_usage_counter
  • Không sửa migration đã merge. Sai thì viết migration mới sửa đè
  • Migration phá vỡ tương thích chia ba bước: thêm cột nullable → backfill → siết ràng buộc
  • Seed tạo 2 Plan, 1 admin, 1 learner demo có sẵn Course + Document + 3 Lesson

07

Thiết kế API

45 endpoint, 8 module. Base /api/v1, version trong path. Mọi lỗi cùng một hình dạng với mã ổn định.

Quy ước chung

Định dạng JSON, camelCase, thời gian ISO-8601 UTC
Xác thực Bearer access token; refresh trong cookie httpOnly
Phân trang Cursor: ?limit=20&cursor= → {items, nextCursor}
Idempotency Header Idempotency-Key bắt buộc cho tạo AIJob và thanh toán
Correlation X-Request-Id có mặt trong mọi log

Định dạng lỗi — RFC 7807 

{
  "code": "QUOTA_EXCEEDED",
  "status": 402,
  "title": "Đã vượt hạn mức",
  "detail": "Gói Free cho phép 5 tài liệu
             mỗi tháng. Bạn đã dùng hết 5.",
  "requestId": "01J8X...",
  "meta": { "limit": 5, "used": 5 }
}

code là chuỗi ổn định để frontend so khớp. Không bao giờ so khớp bằng detail.

Tham số chunking QĐ

Kích thước mục tiêu 1.200 token đủ ngữ cảnh, chưa loãng
Chồng lấn 150 token giữ mạch khi cắt ngang

Mỗi chunk giữ headingPath và khoảng trang — hai trường này cho phép Lesson truy vết ngược về tài liệu gốc, nền tảng của kiểm tra bám nguồn.

Quyết định then chốt QĐ

Tách outline khỏi nội dung — hai lần gọi LLM, không gộp

Giai đoạn A — Outline

1 lần gọi. Đầu vào: heading path toàn bộ chunk + 200 ký tự đầu mỗi chunk. Đầu ra: danh sách node bài học kèm chunkIds.

Giai đoạn B — Lesson + Exercise

n lần gọi, song song tối đa 3. Với mỗi node: gửi toàn văn chunk của node, trả lesson và exercise trong cùng một JSON.

Vì sao tách: outline quyết định cấu trúc khóa học. Gộp chung khiến model vừa lập kế hoạch vừa viết, và kết quả luôn tệ hơn.

Validation — bốn tầng, chạy tuần tự SPEC

Tầng 1 · Schema

Parse bằng Zod. Sai hình dạng thì thử lại ngay, không chấp nhận.

Tầng 2 · Luật nghiệp vụ

  • Đúng một đáp án đúng cho câu trắc nghiệm
  • Không có hai lựa chọn trùng nội dung sau chuẩn hoá
  • Các lựa chọn có độ dài tương đương — không để đáp án đúng dài gấp đôi
  • Không có lựa chọn kiểu "Tất cả đáp án trên"
  • explanation không lặp nguyên văn prompt
  • Tiêu đề Lesson không trùng trong cùng Course

Tầng 3 · Kiểm tra bám nguồn

Mỗi Lesson khai sourceChunkIds, các id phải tồn tại thật. Lấy mẫu 2 thuật ngữ chuyên môn trong contentMd, kiểm tra chúng có trong chunk đã khai không. Dưới 50% khớp → gắn cờ LOW_CONFIDENCE.

Tầng 4 · Vệ sinh dữ liệu

Sanitize Markdown, cắt độ dài quá mức, chuẩn hoá khoảng trắng.

Lesson LOW_CONFIDENCE vẫn được lưu nhưng gắn cờ, và UI hiển thị nhãn "Nội dung này có thể lệch khỏi tài liệu gốc — hãy kiểm tra lại". Đây là cách trung thực để xử lý ảo giác của model, thay vì giả vờ nó không tồn tại.
Retry, timeout và trần chi phí
Tình huống Xử lý
Lỗi schema — tầng 1 Thử lại tối đa 2 lần, prompt lần sau kèm thông báo lỗi cụ thể
Lỗi luật nghiệp vụ — tầng 2 Thử lại 1 lần kèm mô tả luật bị vi phạm
Rate limit từ provider Backoff mũ: 2s, 8s, 30s — tối đa 5 lần
Timeout một lần gọi 120 giây
Timeout toàn job 15 phút → FAILED, code AI_GENERATION_TIMEOUT
Một Lesson hỏng, còn lại ổn Vẫn lưu phần thành công, job SUCCEEDED kèm partialFailures
Toàn bộ Lesson hỏng Job FAILED, không ghi gì vào DB
Vượt AI_JOB_MAX_COST_USD Dừng job, mặc định trần $0.50
Máy trạng thái AIJob — và cách tránh tranh chấp giữa worker

Chuyển trạng thái phải dùng update có điều kiện: 

UPDATE "AIJob" SET status = 'RUNNING', "startedAt" = now()
WHERE id = $1 AND status = 'QUEUED';

Background jobs

Bốn queue, mỗi queue có concurrency và chính sách retry riêng. Worker có thể bị giết bất cứ lúc nào — thiết kế theo giả định đó.

Queue Job Concurrency Timeout Retry
document-extract Trích text, chunk 4 10 phút 3, backoff mũ
lesson-generate Sinh outline + lesson 2 15 phút 2
billing-sync Đồng bộ webhook 2 30 giây 5
maintenance Dọn file tạm, tổng hợp usage 1 5 phút 1

Năm quy tắc bắt buộc cho job

  • Idempotent — chạy lại không tạo dữ liệu trùng
  • Có thể tiếp tục — job dài ghi tiến độ, lần chạy lại không bắt đầu từ số không
  • Không giữ state trong bộ nhớ worker
  • Log kèm jobId và requestId để truy vết từ click của người dùng
  • Dead-letter queue — job hỏng hết số lần thử vào *-dlq, admin chạy lại thủ công

Authentication và bảo mật

IDOR là lỗ hổng phổ biến nhất trong loại ứng dụng này. Đặt bộ lọc quyền sở hữu ở nơi thấp nhất khiến việc quên trở nên khó.

Cơ chế xác thực QĐ

Băm mật khẩu argon2id m=19456, t=2, p=1
Access token JWT 15 phút, giữ trong memory
Refresh token 256 bit, cookie httpOnly; Secure; SameSite=Lax, 30 ngày
Lưu refresh Chỉ lưu SHA-256 hash trong DB
Xoay vòng Mỗi lần refresh cấp mới, thu hồi cũ
Tái sử dụng Dùng lại token đã thu hồi → thu hồi cả familyId

Access token để trong memory chứ không localStorage vì XSS đọc được localStorage. Đổi lại, F5 sẽ mất token — giải quyết bằng gọi /auth/refresh khi app khởi động, vì refresh token nằm trong cookie httpOnly mà script không đọc được.

Phân quyền — đặt ở tầng repository 

// ĐÚNG — không thể quên
findCourseForUser(courseId, userId) {
  return prisma.course.findFirst({
    where: { id: courseId,
             ownerId: userId,
             deletedAt: null },
  });
}

// SAI — dễ quên ở endpoint thứ 20
findCourse(courseId) {
  return prisma.course.findUnique({
    where: { id: courseId } });
}

Kiểm tra Cách làm
Phần mở rộng Danh sách trắng: .pdf .pptx .docx .txt .md
MIME Đối chiếu header với phần mở rộng

Danh sách kiểm tra bảo mật — 15 mục
  • Mọi endpoint (trừ auth, /plans, /health, webhook) yêu cầu access token hợp lệ
  • Mọi truy vấn tài nguyên lọc theo ownerId ở tầng repository
  • Đáp án đúng không xuất hiện trong response nào trước khi nộp bài
  • Giá lấy từ Plan.priceCents trong DB, không lấy từ request
  • Webhook xác minh chữ ký và ghi PaymentEvent trước khi xử lý
  • Rate limit: đăng nhập 5/phút/IP · tạo AIJob 10/giờ/user · API chung 100/phút/user
  • Helmet, CORS chỉ cho phép origin đã cấu hình
  • Zod validate mọi input, kể cả param đường dẫn
  • Prisma tham số hoá sẵn — không nối chuỗi SQL ở bất cứ đâu
  • Markdown từ LLM sanitize trước khi render bằng rehype-sanitize
  • Không có secret trong repo; .env.example chỉ chứa key rỗng
  • Log không chứa mật khẩu, token, hay toàn văn tài liệu người dùng
  • Lỗi đăng nhập không phân biệt "sai email" với "sai mật khẩu"
  • Dependency scan chạy trong CI
  • Header bảo mật: X-Content-Type-Options, X-Frame-Options, CSP

DevOps và CI/CD

Thứ tự deploy an toàn: migration → worker → api → web. Worker lên trước để không job nào rơi vào phiên bản code cũ.

Chạy môi trường local

git clone <repo> && cd learn
cp .env.example .env      # điền LLM_API_KEY
npm install
docker compose -f infra/docker-compose.yml up -d
npm run db:migrate
npm run db:seed
npm run dev               # web :3000 · api :4000

docker-compose.yml phải chạy được trên máy sạch, không cần cài thêm gì ngoài Docker và Node. Đây là tiêu chí trong Definition of Done của spec.

Pipeline CI

PR mở
├── lint        eslint + prettier      ~1 phút
├── typecheck   tsc --noEmit           ~2 phút
├── test:unit   vitest                 ~2 phút
├── test:int    vitest + testcontainers ~4 phút
├── build       next build + nest build ~3 phút
├── audit       npm audit --high       ~1 phút
└── e2e         playwright (PR vào main) ~6 phút

CI đỏ thì không merge. Không có ngoại lệ, không "để sửa sau".

Thành phần Nơi chạy Ghi chú

Vận hành

requestId đi xuyên suốt: HTTP request → job trong queue → lần gọi LLM. Không có nó thì không thể trả lời "vì sao bài học của người dùng này bị hỏng".

Chỉ số Ngưỡng cảnh báo

Quy ước kỹ thuật

Comment giải thích vì sao, không giải thích cái gì. Code tự nói được cái gì.

Đặt tên

Bảng và model PascalCase số ít DocumentChunk

Thuật ngữ nghiệp vụ trong tên phải khớp từ điển mục 01. Không có Quiz, không có Class.

Quy ước code

  • TypeScript strict: true. Không dùng any — không qua được lint
  • Tầng: controller → service → repository. Không nhảy tầng
  • Controller không chứa logic nghiệp vụ; service không biết gì về HTTP
  • Mọi input ngoài hệ thống đi qua Zod, kể cả response của LLM
  • Lỗi là exception có kiểu, filter toàn cục chuyển sang định dạng chuẩn

Git: main luôn deploy được · Conventional Commits · một PR một việc · PR quá 400 dòng nên tách · merge bằng squash.

Checklist review PR — 11 mục

  • CI xanh toàn bộ
  • Có test cho hành vi mới; test thất bại trước khi sửa, xanh sau khi sửa
  • Không có any, không có console.log sót lại, không có code chết
  • Truy vấn dữ liệu có lọc quyền sở hữu
  • Không lộ đáp án đúng ra response
  • Lỗi trả về đúng định dạng với code ổn định
  • Có xử lý đủ 5 trạng thái UI nếu là màn hình có dữ liệu
  • Không có secret, không có URL production hardcode
  • Thay đổi này có tạo ra tuyên bố nào về sản phẩm mà code chưa làm được không?
  • Nếu đổi schema: có migration, chạy được cả chiều tiến lẫn rollback
  • Nếu đổi prompt: đã tăng version prompt và chạy lại bộ đánh giá
ADR — Architecture Decision Records. Mỗi quyết định QĐ đáng kể ghi một file trong docs/adr/: bối cảnh, quyết định, hệ quả tốt/xấu, và "sẽ xem lại khi". Năm ADR đầu tiên cần viết: TypeScript toàn bộ · Monorepo · Tách outline · Webhook là nguồn sự thật · Quyền sở hữu ở tầng repository. Đây chính là nội dung cho section 12 của portfolio website — viết luôn khi ra quyết định rẻ hơn nhiều so với dựng lại từ trí nhớ sau ba tháng.

Rủi ro

Ba rủi ro đáng lo nhất đều xoay quanh AI pipeline. Nguyên tắc lập lịch quan trọng nhất: chạy thử pipeline với tài liệu thật càng sớm càng tốt.

# Rủi ro Khả năng Mức độ Giảm thiểu
R1 Chất lượng bài học AI sinh không dùng được Cao Nghiêm trọng Tách outline khỏi nội dung; 4 tầng validation; bộ đánh giá chạy sớm từ T6; cho người dùng sửa bài; gắn cờ LOW_CONFIDENCE thay vì giấu
R2 Trích xuất PDF kém với tài liệu thật Cao Nghiêm trọng Thử 10+ PDF thật ngay ở M2; có tiêu chí và lối thoát sang parser Python; sẵn sàng thu hẹp còn PDF có text layer
R3 Chi phí LLM vượt dự tính Trung bình Vừa Ghi GenerationRun từ đầu; trần chi phí mỗi job; hạn mức theo gói; model rẻ cho việc nhẹ
R4 Mốc M3 trượt kéo theo toàn bộ lịch Trung bình Nghiêm trọng 1 tuần đệm; lộ trình rút gọn 6 tuần là phương án B
R5 OCR quá chậm, job timeout Trung bình Vừa Giới hạn 50 trang scan; báo lỗi rõ thay vì treo
R6 Rate limit LLM provider chặn khi demo Thấp Vừa Backoff mũ; giới hạn song song 3; chuẩn bị dữ liệu demo sinh trước
R7 Phạm vi phình ra Cao Vừa Danh sách ngoài phạm vi là chốt; đề xuất mới vào roadmap, không vào sprint đang chạy
R8 Website tuyên bố quá đà so với code Trung bình Nghiêm trọng Dòng cuối trong checklist review PR; 4 nhãn trạng thái; kiểm chứng bằng 3 người
R9 Lộ đáp án đúng ra client Trung bình Nghiêm trọng DTO riêng cho hai chế độ đọc; test E2E kiểm tra response
